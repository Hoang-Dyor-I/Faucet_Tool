## 2025-02-05 - Masking URL-Encoded Credentials in Exception Logs
**Vulnerability:** Exception traceback printing directly logs `Exception` objects via string interpolation (`f"{e}"`). This can leak plaintext or URL-encoded passwords if errors are emitted from libraries like `requests` handling proxies.
**Learning:** `requests` automatically percent-encodes credentials in ProxyError exceptions, meaning standard plaintext string masking (e.g. `user:pass`) fails. The regex must account for percent-encoded formats. Furthermore, parsing custom proxy inputs manually with simple `.split(":")` is vulnerable to injection if the password itself contains a colon. Use `.split(":", 3)` and always encode proxy strings explicitly via `urllib.parse.quote`.
**Prevention:** Use `re.sub` with a general pattern like `r'(://[^:]+:).*?(@[^@/]+(?:/|$))'` to safely mask both plaintext and URL-encoded credentials in error logs before printing them. Always URL encode components during proxy instantiation.
