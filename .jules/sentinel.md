## 2024-11-06 - Proxy Credential Leakage in Exception Handling
**Vulnerability:** Proxy passwords containing special characters were not URL-encoded in basic auth, and unhandled `requests` exceptions printed the full exception object, exposing the proxy plaintext credentials in standard output logs.
**Learning:** The `requests` library incorporates proxy credentials into URLs for connection errors, meaning printing the raw exception will inadvertently log passwords. Furthermore, basic auth strings containing special characters like `@` or `:` can break URL parsing if not correctly percent-encoded, and regex masking needs to account for this encoding.
**Prevention:** Always percent-encode basic auth credentials using `urllib.parse.quote` before constructing connection URLs. When logging or printing exceptions that involve network requests, explicitly catch and sanitize the exception string using a robust regex pattern (e.g., `re.sub`) to mask sensitive credentials before output.
