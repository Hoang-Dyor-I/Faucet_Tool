## 2024-06-25 - Prevent proxy credential exposure in devnet tool
**Vulnerability:** Proxy strings containing usernames and passwords (user:pass format) were printed directly to console logs during loop initialization, and raw error objects were logged on connection failures. Furthermore, malformed proxies could trigger internal errors or inadvertently bypass local request restrictions.
**Learning:** Hardcoded text logging assumes strings are safe; complex objects like URLs/proxies inherently contain embedded secrets that developers miss when focusing purely on the network path. Lack of defensive validation combined with verbose default exceptions leads to secrets sprawling across CI/CD or local terminal output.
**Prevention:** Implement a mandatory masking wrapper before logging any configuration that contains authentication layers. Use specific boundary validation for connection objects (like ensuring 4 colon-separated elements) and generic, hardcoded strings for fallback failure states instead of dynamic exception messages.
