## 2024-03-28 - Information Exposure via Console Logs and Exception Handling
**Vulnerability:** The script previously printed raw proxy configurations, which included plaintext passwords, to stdout during every loop iteration. Additionally, any network exception (`requests.exceptions.RequestException`) directly logged the stack trace or unhandled string output to stdout, exposing potential system state and local environments.
**Learning:** These vulnerabilities often exist because developers optimize for functional clarity during initial development, relying heavily on standard outputs to trace execution state, without actively auditing the sensitive nature of the state variables (credentials) passing through those log statements.
**Prevention:** Establish a project-wide convention to sanitize any authentication strings (URLs, proxy headers) via dedicated helper functions (e.g., `mask_proxy`) before logging. Replace direct exception stringification in console output with generic error messages combined with secure, internal-only error tracking (where available).
