## 2024-05-24 - Unencoded Proxy Credentials and Leakage in Logging
**Vulnerability:** Proxy passwords containing special characters (like '@') were not percent-encoded, causing invalid proxy URL construction. Additionally, unmasked credentials in proxy strings were logged to the console natively, and raw proxy connection exceptions from the `requests` library leaked full URLs containing plain-text credentials.
**Learning:** Raw string manipulation of connection strings requires explicit encoding (`urllib.parse.quote`) to ensure valid URL syntax. Full exception objects from networking libraries often embed the problematic URL intact, bypassing simple print-level masking.
**Prevention:** Always percent-encode credentials before interpolating into URLs. Separate proxy credential parsing from logging by using a specific masking function (`mask_proxy`). Sanitize network exception messages with regex (`re.sub(r'(://[^:]+:).*?(@)', r'\1***\2', str(e))`) to strip credentials while preserving debugging context.
