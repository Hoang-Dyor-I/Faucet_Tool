## 2024-05-18 - Proxy Credential Leakage in Logs and Exceptions
**Vulnerability:** Proxy credentials (passwords) were logged in plaintext directly to the console when switching proxies, and `requests` exception messages leaked URL-encoded proxy passwords when connection errors occurred. Additionally, credentials were not URL-encoded in proxy dictionaries, leading to potential injection issues with special characters.
**Learning:** `requests` automatically percent-encodes credentials in exception URLs, meaning regex sanitization must account for percent-encoded characters like `%40`. Global file I/O causes side-effects during imports in Python tests, so state should be encapsulated in `main()`. Proxy parsing needs `maxsplit` to avoid truncating passwords containing delimiters.
**Prevention:** Pre-parse proxies into dictionaries and URL-encode credentials using `urllib.parse.quote(val, safe='')`. Create a `mask_proxy` function to redact passwords before general logging. Use regex to strip credentials from raw exception strings before printing (e.g., `re.sub(r'(://[^:]+:).*?(@[^@/]+(?:/|$))', r'\1***\2', str(e))`). Avoid global file reads in scripts.
