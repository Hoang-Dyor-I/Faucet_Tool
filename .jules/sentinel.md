## 2024-05-18 - Prevented Proxy Credential Exposure and Injection
**Vulnerability:** Proxy credentials (username/password) were being directly interpolated into strings without URL-encoding, which can cause request failures or injection vulnerabilities if passwords contain special characters like `@` or `:`. Additionally, raw proxy strings containing passwords were being printed in console logs, exposing credentials. Exception handling was also too verbose and could leak server/proxy details in output.
**Learning:** Hardcoded string interpolation for proxy credentials in `requests` can break parsing if special chars are present. A password must be properly URL-encoded. Passwords must never be logged verbatim.
**Prevention:** Always use `urllib.parse.quote(val, safe='')` to sanitize credentials used in proxy authentication strings. Ensure logging operations pass through a sanitization function (`mask_proxy`) to obfuscate passwords. Use generic failure messages for broad `Exception` catches.
