## 2024-10-19 - Critical vulnerability: Plaintext proxy credentials leaking in logs and exceptions
**Vulnerability:** The Solana devnet script was vulnerable to credential leaking. The proxy string (which includes the plaintext password) was being printed directly to the console during execution, and more critically, unhandled connection exceptions from the `requests` library could expose the full URL with the plaintext proxy password in the stack trace. Additionally, passwords with special characters (like `:` or `@`) were not properly URL-encoded or split, leading to functional bugs and potential injection vulnerabilities.
**Learning:** Hardcoded or dynamically read secrets MUST be masked before logging. The `requests` library automatically percent-encodes credentials in its error output, meaning regex maskers must account for URL-encoded characters (like `%40` for `@`). Simple string splitting (`split(":")`) fails when passwords contain the delimiter.
**Prevention:** Always use `urllib.parse.quote` to percent-encode passwords in URLs. Use `split(":", 3)` to ensure passwords containing colons are not incorrectly truncated. Implement a dedicated masking function (e.g., replacing the password part with `***`) before logging any proxy strings. Implement a regex-based sanitizer in exception blocks (e.g., `re.sub(r'(://[^:]+:).*?(@[^@/]+(?:/|$))', r'\1***\2', str(e))`) to securely redact credentials from raw exception messages before printing them to the console.
