## 2024-05-24 - Missing Credential Sanitization in Proxy Error Logs
**Vulnerability:** Proxy credentials (username and password) are passed into Python `requests` library in plain text within a URL structure and are logged to console without masking. Additionally, exceptions thrown by `requests` embed full URL strings with plaintext passwords in their messages which are printed out directly.
**Learning:** `requests` automatically percent-encodes credentials in its error output, but does not fully redact passwords from its stacktraces or error strings. Any script that handles proxies with authentication must explicitly sanitize both its own stdout prints and stringified `Exception` messages before printing them to the user.
**Prevention:** Implement a regex-based sanitization wrapper for all error logs `re.sub(r'(://[^:@/]+:)[^:@/]+(@)', r'\1***\2', str(e))` and use a dedicated `mask_proxy` function to redact passwords before outputting any proxy-related status messages.
