## 2024-05-24 - Mask Proxy Credentials in Logs and Encode for URLs
**Vulnerability:** Proxy credentials (username/password) were being logged in plaintext during normal script execution and in exception tracebacks (e.g., from `requests` errors). Additionally, credentials with special characters were inserted directly into proxy URLs without URL encoding.
**Learning:** Hardcoding or direct string formatting of sensitive credentials into URLs without encoding leads to malformed URLs if special characters are present. Logging exceptions directly without sanitization can inadvertently expose sensitive data like passwords included in URLs.
**Prevention:** Always percent-encode credentials before inserting them into URLs using `urllib.parse.quote(..., safe='')`. When logging potentially sensitive strings or handling exceptions from network libraries, utilize regex sanitization (e.g., `re.sub(r'(://[^:]+:).*?(@)', r'\1***\2', str(e))`) to mask passwords while preserving debugging context. Ensure masking happens immediately upon reading configuration and prior to any print statements.
