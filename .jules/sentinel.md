## 2024-04-08 - Proxy Credential and Internal Error Exposure in Logs
**Vulnerability:** Proxy credentials (username/password) were printed in plain text during execution logs, along with raw exception details in failure cases which leaked stack trace specifics. In addition, malformed proxies could cause script crashes or send network requests that bypass the proxy entirely, potentially exposing the local IP. Finally, file reads upon import could cause unwanted side effects if the script was just imported as a module.
**Learning:** These existed because the application blindly printed full proxy strings and exception objects directly into its formatted log outputs without sanitization. Further, proxy configuration validity wasn't checked before executing network requests.
**Prevention:** Implement defensive proxy masking functions specifically for log outputs, check proxy validity and fail securely to prevent IP leakage, strictly log error types rather than raw strings, and encapsulate setup logic into the `main` block.
