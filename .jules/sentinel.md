## 2024-05-24 - Masking Sensitive Credentials in Logs and URLs
**Vulnerability:** Proxy credentials (username and password) were being concatenated directly into URLs unencoded. Additionally, exception strings thrown by libraries like `requests` were being logged without sanitization, leaking these unencoded credentials in plaintext directly to standard output.
**Learning:** Hardcoded/unencoded injection of credentials into connection strings can cause exceptions if passwords contain URL-sensitive characters (like `@` or `:`). Further, when exceptions bubble up and log the URL, they compromise system security by writing these plaintext credentials to logs/consoles. Also, `.split(":")` needs `maxsplit` if passwords can contain colons.
**Prevention:** Always percent-encode user credentials using `urllib.parse.quote()` before including them in a URL string. When logging exceptions related to connection errors, implement string sanitization (like Regex `re.sub(r'(://[^:@/]+:)[^:@/]+(@)', r'\1***\2', str(e))`) to mask passwords. Finally, manually mask any direct logging of proxy strings using string parsing, and explicitly use `maxsplit=3` when destructuring credential strings.
