## 2024-05-24 - [CRITICAL] Proxy Credential Exposure in Logging and Exception Handling
**Vulnerability:** The script was printing out raw proxy connection strings containing basic authentication credentials (`user:password`) to the console. Furthermore, it printed the raw `Exception` object `e` during proxy connection failures. The `requests` library's `ProxyError` objects often contain the full auth proxy URL, causing an unintended credential leak.
**Learning:** Always explicitly mask or avoid logging full connection strings containing user credentials. Never blindly print `Exception` objects directly to stdout/logs when dealing with authenticated proxies, databases, or API clients, as their tracebacks and string representations frequently leak sensitive tokens and URLs.
**Prevention:** Sanitize strings containing URLs or proxy details before printing them. Catch specific exceptions when possible, or log a generic error message and only store stack traces in a secure diagnostic file rather than standard output.
