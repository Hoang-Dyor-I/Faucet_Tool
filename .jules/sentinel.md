## 2024-05-24 - Proxy Credential Exposure in Requests Library
**Vulnerability:** Proxy passwords containing special characters were not URL-encoded before being used in proxy connection URLs, leading to malformed URLs or connection errors. Furthermore, complete proxy connection strings, including plaintext username and password, were being printed directly to the console output and leaked in raw exception messages generated by the `requests` library.
**Learning:** The `requests` library naturally includes the proxy URL in exception messages when a connection fails. When reading connection strings directly from a configuration file and interpolating them into HTTP scheme templates, any embedded credentials (especially those with characters like '@' or ':') must be properly encoded to form valid URLs. It is a critical security vulnerability to expose connection credentials in terminal output or log files.
**Prevention:** Always parse proxy strings and URL-encode the `username` and `password` components using `urllib.parse.quote` before interpolating them into the proxy URL string. For console output or logging, apply a string masking function to the proxy string or sanitize the output with regex to obscure the password portion (e.g., `user:***` instead of `user:password`). Catch and sanitize exceptions explicitly to prevent the `requests` library from inadvertently exposing secrets in its traceback messages.
