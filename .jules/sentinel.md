## 2024-05-24 - Proxy Credential Exposure in Logs
**Vulnerability:** Proxy credentials (username/password) were being printed in plaintext to the console via both standard logging and uncaught request exceptions. Additionally, the proxy parsing logic failed on passwords containing colons (`:`).
**Learning:** 1. `requests` exceptions stringify the full URL, including credentials, which can bypass simple print redaction if the exception itself isn't masked. 2. Simple `split(":")` is insufficient for parsing delimited strings when the final segment (like a password) might legitimately contain the delimiter character. 3. Passwords with special characters need to be URL encoded before being injected into a proxy string to avoid misinterpretation by requests.
**Prevention:** Always implement a dedicated masking function for logging sensitive URIs, and sanitize exception messages via regex `re.sub(r'(://[^:]+:).*?(@[^@/]+(?:/|$))', r'\1***\2', str(e))` before logging. Use `.split(":", maxsplit=3)` for bounded parsing, and `urllib.parse.quote` to percent-encode credentials.
