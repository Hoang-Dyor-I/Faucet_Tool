## 2024-05-18 - Prevent Proxy Credential Leakage in Exception Messages
**Vulnerability:** Proxy credentials (username and password) were being leaked in plaintext via console logs when the `requests` library raised connection exceptions, as the exception string includes the requested proxy URL. The raw proxy string was also logged during batch initialization without masking the password.
**Learning:** In Python, the `requests` module injects full proxy URLs (including credentials) into network-related exception messages (e.g., `requests.exceptions.ProxyError`). Simply printing an exception object (e.g., `print(f"Error: {e}")`) is an anti-pattern that can expose sensitive authentication data.
**Prevention:** Always sanitize exception messages containing URLs using non-greedy regex replacement (e.g., `re.sub(r'(://[^:]+:).*?(@)', r'\1***\2', str(e))`) before logging. Additionally, proxy credentials should be percent-encoded to support special characters, pre-parsed to dictionaries to avoid redundant string splitting, and masked explicitly (replacing the password segment with `***`) during status logs.
