## 2024-09-08 - Proxy Credential Leakage in Logs and Exception Messages
**Vulnerability:** Proxy passwords containing special characters were exposed in plaintext on the console during proxy switching. Furthermore, unhandled exceptions from the `requests` library when using proxies with embedded credentials (e.g., connection errors) exposed the full proxy URL including the plaintext username and password.
**Learning:** Hardcoded print statements displaying full proxy strings directly expose sensitive credentials. The `requests` library incorporates proxy URLs within its exception messages (like `ProxyError`), leading to inadvertent logging of credentials. When constructing URLs from strings, failure to URL-encode characters like `@` or `:` in passwords can lead to malformed URLs and broken proxy connections, or trigger unexpected parsing errors that dump the string.
**Prevention:** Always parse sensitive credential strings (like proxy configurations) into their constituent parts and manually redact or mask the password field (e.g., replacing with `***`) before logging or displaying them. For exception handling, sanitize the exception string representation using a regex (e.g., `re.sub(r'(://[^:]+:).*?(@[^@/]+(?:/|$))', r'\1***\2', str(e))`) before outputting it. Always `urllib.parse.quote` credentials before embedding them in URLs to prevent injection-like issues and guarantee valid URL construction.
