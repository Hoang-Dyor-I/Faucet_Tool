## 2024-07-01 - Prevent Credential Leakage in Exception Stack Traces and Logs
**Vulnerability:** Hardcoded credentials exposed via exception tracebacks when `requests.post()` failed, and clear-text credentials were unintentionally logged during proxy initialization. In addition, credentials containing special characters weren't URL encoded.
**Learning:** Network exception logs and direct prints of configuration objects often contain fully resolved URLs which leak secrets. It's not enough to just handle errors; the errors themselves must be scrubbed of sensitive data using regex before being outputted. Also, special characters in proxy passwords can break URL parsers.
**Prevention:** Always URL-encode credentials used in proxy configurations (`urllib.parse.quote()`). Proactively scrub logged exceptions matching known credential patterns (`re.sub(r'(://[^:]+:).*?(@)', r'\1***\2', str(e))`) and provide custom masking functions for logging objects with sensitive attributes.
