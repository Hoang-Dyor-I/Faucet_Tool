## 2024-10-21 - Secure Proxy Credential Handling and Exception Sanitization
**Vulnerability:** Proxy credentials (username/password) were printed in plaintext to the console via `print(f"\n🌐 Đang dùng proxy: {proxy}")`, and potentially leaked via `Exception` logging (`print(f"⚠️ Lỗi proxy hoặc kết nối cho {wallet} - {e}")`) which typically includes the full proxy URL (e.g. from `requests` ProxyError). Additionally, user credentials containing special characters weren't URL encoded, potentially breaking proxy string parsing/URLs, and string splitting was unsafe for passwords with colons.
**Learning:** Hardcoded logs or generic exception catching (`except Exception as e: print(e)`) often inadvertently leak sensitive tokens/passwords embedded in URLs or configuration strings.
**Prevention:** Always mask credentials (`***`) before logging (`mask_proxy`). For exception logging, use regex sanitization to scrub passwords from URLs present in error messages. Always use `urllib.parse.quote()` on credentials injected into URLs. Use `maxsplit` (e.g., `split(":", 3)`) to ensure passwords with delimiter characters aren't improperly truncated.
