## 2024-04-02 - Exposed Proxy Credentials in Logs and Exception Traces
**Vulnerability:** Proxy strings containing plaintext credentials (`user:password`) were being logged verbatim directly to standard output via `print` statements in the script execution loop. Additionally, the broad `Exception` handler was capturing and printing the exception object natively which could theoretically expose environment/proxy credentials depending on the request library behavior. Lastly, an improperly formatted proxy string could fail the tuple unpacking and crash or pass a malformed object into `request_faucet`, causing fallback connection behavior.
**Learning:** Developers often forget that full configuration strings logging exposes included secrets. Catch-all exception blocks that stringify the exception object (`{e}`) create a leak channel for underlying network implementation details.
**Prevention:** Always mask out the `user:password` segment inside structural credentials before applying them to output logs. Restrict error handling payloads to generic, non-introspective user messaging (e.g. `⚠️ Lỗi proxy hoặc kết nối`). Implement validation at the boundaries before generating complex objects.
