## 2024-05-18 - Fix Proxy Credential Exposure and Injection Vulnerabilities
**Vulnerability:** Proxy credentials (username and password) were concatenated unencoded into proxy authentication URLs, which introduces injection risks when special characters (like `@` or `:`) are used. In addition, raw proxy strings containing passwords were fully exposed in standard console logging during script initialization, and complete proxy URLs (including plaintext credentials) were susceptible to leaking via the `requests` library exception outputs on failure.
**Learning:** These vulnerabilities often arise when network scripts directly log input variables without sanitization and form URLs via direct string interpolation instead of utilizing robust URL encoding modules (`urllib.parse.quote`). Additionally, external library errors frequently embed complete configuration contexts, inadvertently dumping sensitive data into standard output.
**Prevention:** Always isolate, strictly percent-encode, and properly sanitize any sensitive configuration strings before URL assembly. Actively employ proxy credential masking functions prior to standard logging, and specifically use tailored regex patterns to scrub embedded URLs from unhandled exception texts to ensure a secure failing posture.
