## 2024-03-22 - Sensitive credential exposure via untrusted external configurations and raw stack trace logging
**Vulnerability:** The script blindly accepted proxy configurations string (`host:port:user:pass`) loaded from `proxies.txt` and systematically logged them in plaintext directly to standard output. Additionally, generic Python exception stack traces and unhandled remote API responses (`response.text`) were caught and printed directly in error logs.
**Learning:** Hardcoded credentials and untrusted exception sources can expose deep infrastructure details, especially when automated bots/scripts execute remotely. By logging unparsed configurations, user:pass auth combinations are leaked. Exposing bare remote service HTTP responses or generic script exception traces introduces unnecessary intelligence leakage.
**Prevention:** All inputs handling explicit secrets/credentials must be masked (`***`) at the variable assignment level before they ever reach logging mechanisms. Similarly, try-except blocks must capture errors and re-throw, log, or return specific generic failure indicators instead of arbitrary remote endpoints' unfiltered `Exception` or `response.text`.
