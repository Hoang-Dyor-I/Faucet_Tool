## 2024-04-18 - Fix credential exposure and IP leakage in proxy handling
**Vulnerability:** Proxy strings containing plaintext credentials (username:password) were being printed directly to the console. Furthermore, malformed proxy configurations could result in the program inadvertently bypassing the proxy entirely due to uncaught parsing exceptions, causing network requests to fall back to using the local IP address without the proxy in a restricted or sensitive execution environment. Lastly, printing the full exception object string directly to logs leaked internal technical or path information instead of just generic exceptions.
**Learning:** Raw application configuration variables should never be passed blindly into logging functions; they must be sanitized. Rate limiting delay implementations must be strictly preserved across all early exit conditions in network-heavy worker threads to avoid overwhelming servers or creating local tight loops when connections fail gracefully. Catch-all `except Exception as e:` blocks should not log `e` natively as doing so can expose stack trace text or internal details.
**Prevention:** Implement string parsing or regex sanitizers (like a `mask_proxy` function) on credentials before log output. Always enforce `type(e).__name__` instead of full object string conversions for sensitive catch-all exceptions. Consistently encapsulate worker thread logic with `try/finally` blocks or enforced delay routines to preserve rate limiting logic even when preconditions fail.
