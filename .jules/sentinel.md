## 2024-05-18 - Fix exposed proxy credentials and response data in logs
**Vulnerability:** The script `Sol_Devnet.py` was logging the full proxy string, which could contain `user:password` credentials in the format `host:port:user:password`. Additionally, the full response text was being logged on failure, and exception messages were printed directly, which might leak internal system information or full proxy URLs containing credentials.
**Learning:** The vulnerability existed because generic error handling and broad log statements (like printing `proxy` and `response.text` or exception `e`) were used without sanitization. Developers often log everything during debugging and leave it in production.
**Prevention:** Always parse or split sensitive strings (e.g., proxy configurations) to isolate and mask credentials (`user:pass`) before logging. Use safe, generic error messages instead of printing full exception objects to prevent internal information exposure. Sanitize or limit the output of external API responses.
